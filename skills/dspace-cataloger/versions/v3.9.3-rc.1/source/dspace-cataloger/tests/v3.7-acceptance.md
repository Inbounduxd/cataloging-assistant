# dspace-cataloger v3.7 — Acceptance

1. Runtime Mode no navega fuentes externas para afirmar hechos de la colección.
2. El agente runtime no crea/modifica drafts, suggestions, reviews, vocabularios ni sesiones de evidencia.
3. Los cinco campos lingüísticos runtime se preservan literalmente.
4. `dc.subject.linguiscgroup` permanece literal.
5. `dc.subject.linguisticVariant` es runtime draftable/profiled/vocabularied y no produce `APP_SCHEMA_GAP`.
6. Variant no presume `linguisticVariantPairs`; vocabulario local activo gobierna si existe.
7. Los únicos evidence states son `EXTRAÍDO`, `VERIFICADO`, `INFERIDO`, `PENDIENTE`, `GENERADO`.
8. `APP_SCHEMA_GAP` no es evidence state.
9. Un vocabulario bundled no se presenta como vocabulario activo runtime.
10. `metadata-validation=invalid` no se corrige con fuzzy matching.
11. Un draft o evidence session stale no se rebasa automáticamente.
12. Las sesiones de evidencia congelan fuente con hash y versión de contrato.
13. Fuentes y candidatos poseen orden lógico estable por `position`, único por sesión.
14. La extracción repetida devuelve el snapshot existente con los mismos candidate IDs/orden.
15. `binding_id` es obligatorio para resolver claves compartidas como `dc.subject` y `dc.format.medium`.
16. `copy-to-draft` solo admite `runtime_draftable`.
17. `copy-to-draft` revalida contra el vocabulario activo actual y ordena por `candidate.position`.
18. Un cambio de `base_source_hash` bloquea extracción/copia de una sesión ligada a ítem.
19. El MVP runtime no realiza fetch remoto de URL, upload/parsing PDF/binario ni extracción LLM.
20. Standalone Mode conserva adquisición de URL/PDF y salida completa UI Fidelity.
21. Ningún cambio rompe GR01–GR20 ni form-contract acceptance.
22. Se preservan los 56 bindings y los controles compartidos no se colapsan.
23. Ninguna regla acopla semántica catalográfica a Anthropic/OpenAI.
24. Ninguna regla habilita escritura DSpace.
