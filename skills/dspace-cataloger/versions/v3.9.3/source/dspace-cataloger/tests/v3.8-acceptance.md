# dspace-cataloger v3.8 — Acceptance

## Contract regression

- [ ] Los 56 bindings del form contract permanecen sin cambios.
- [ ] `dc.subject.linguiscgroup` permanece literal.
- [ ] Los cinco campos lingüísticos runtime permanecen independientes.
- [ ] Estados canónicos: EXTRAÍDO, VERIFICADO, INFERIDO, PENDIENTE, GENERADO.

## VERTICAL-019 — local PDF

- [ ] Runtime reconoce PDF local como evidencia controlada por superficie humana.
- [ ] Extracción runtime es determinista y text-only.
- [ ] Provenance por página se conserva cuando existe.
- [ ] `no_extractable_text` no promete ni dispara OCR.
- [ ] El agente conversacional no sube ni muta PDF evidence.

## VERTICAL-020 — secure remote fetch

- [ ] Fetch remoto se describe como explícito, backend-only y feature-flagged off por defecto.
- [ ] SSRF/DNS/IP/redirect/MIME/size/time guards pertenecen al backend.
- [ ] Cada fetch crea snapshot append-only e inmutable.
- [ ] Re-fetch de la misma URL no sobrescribe la fuente histórica.
- [ ] Cambiar el origen remoto no vuelve stale un snapshot histórico.
- [ ] Staleness canónico permanece a nivel de Evidence Session vs DSpace source hash.
- [ ] Provenance remota admite requested/final URL, media type, bytes, fetched_at, hash y redirect metadata.
- [ ] El agente conversacional no ejecuta fetch ni mutaciones de evidencia.

## Safety boundaries

- [ ] No OCR en Cataloging Assistant Runtime Mode.
- [ ] No LLM-assisted extraction en el baseline actual.
- [ ] No persisted Accept/Reject como contrato del agente.
- [ ] No escritura DSpace.
- [ ] Standalone capabilities no amplían permisos runtime.

## Package integrity

- [ ] Todos los JSON del paquete parsean correctamente.
- [ ] Golden Set previo se preserva sin reemplazo.
